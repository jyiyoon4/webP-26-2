# 사용자 정의

> 과제 조건: 고등학생에게는 학과를 알리고, 재학생에게는 필요한 정보를 찾게 한다. ([[안 B 조건]])

## 👩‍🎓 주 사용자: 진학할 학과를 알아보는 고3
| 항목 | 내용 |
|---|---|
| 상황 | 원서 쓰기 전, 휴대폰으로 학과 사이트를 둘러본다 |
| 하려는 일 | ① 무엇을 배우는지 ② 누가 가르치는지(교수 · 연구실) ③ 졸업 후 어디로 가는지 |
| 지금 겪는 불편 | 이 세 가지가 메뉴 4곳에 흩어져 있다. 용어(CDR, 1전선, PBL)가 낯설다. 모바일 화면이 깨진다 |
| 필요한 것 | 한 흐름으로 이어지는 소개, 학년별로 보는 교육과정, 쉬운 말 |

## 🧑‍💻 보조 사용자: 소프트웨어학과 재학생 (= 평가자)
| 항목 | 내용 |
|---|---|
| 상황 | 수강신청 전, 다음 학기 과목과 교수 연구실을 확인한다 |
| 하려는 일 | ① 학년 · 학기별 과목과 해설 확인 ② 교수 연구실 위치 · 연구 분야 확인 ③ 공지 · 학사일정 바로가기 |
| 지금 겪는 불편 | 학년 탭을 누를 때마다 페이지가 새로 로딩된다. 과목 해설을 보려면 페이지를 왔다 갔다 해야 한다 |
| 필요한 것 | 빠른 탭 · 필터, 과목을 누르면 바로 펼쳐지는 해설 |

> [!tip] 전략
> 평가는 **재학생의 선호도 투표**다. 기획 문서상 주 사용자는 고3으로 두더라도, 재학생이 직접 써보고 "이게 낫다"고 느낄 기능(교육과정 탭 + 해설 펼치기, 교수 · 연구실 통합)을 핵심으로 잡는다.
