# 기말 프로젝트 개요

> 실제로 있는 사이트를 우리 손으로 다시 기획하고 만든다.

| 항목 | 내용 |
|---|---|
| 팀 | 2인 1팀 |
| 주제 | 두 안 중 하나: 안 A 기업 홈페이지(펜테크), **안 B 학과 홈페이지** ✅ |
| 만드는 것 | 여러 쪽짜리 정적 사이트 (HTML · CSS · 간단한 자바스크립트) |
| 배포 | 팀 저장소의 `site/` → **smu.ai.kr** |
| 기획안 | 9주 50% → 11주 70% → 13주 90% → 14주 100% |
| 발표 | 15주: 데모 · 저장소 이력 · 검수표 |
| 평가 | 안 B는 **소프트웨어학과 학생들이 선호도를 평가**한다 |

## 왜 실제 사이트인가
- **사용자와 내용이 이미 있다.** 누가, 무엇을 하러 오는지 실제로 따져볼 수 있다. 지어낸 주제보다 목적과 사용자를 쓰기 쉽다.
- **비교할 대상이 있다.** 지금 사이트의 불편한 점을 찾는 것이 기획의 출발점이다. 「무엇을 더 잘할 것인가」가 우리 사이트의 목적이 된다.
- **그대로 옮기는 것이 아니다.** 메뉴를 다 만들지 않는다. 사용자에게 중요한 **4~6쪽만 골라 다시 설계**한다.

## 주제 정하는 날 할 일
- 두 사이트를 같이 열어보고 10분 동안 이야기한다. 어느 사용자를 더 잘 이해할 수 있는가, 무엇을 더 잘 만들 수 있는가.
- `docs/기획안.md`
  - 「1. 목적」 첫 줄에 **주제와 고른 이유**를 쓴다.
  - 「2. 사용자」에 **지금 사이트에서 불편한 점 세 가지**를 쓴다. → [[불편한 점 TOP3]]
- 실습 Step 7의 기획안 50%를 이 주제로 쓴다.

## 일정 메모
- 2026-2학기 개강을 9/1로 잡으면 11/26은 **13주차 무렵**이다. 기획안 90% 시점이다.
- 실제 주차와 제출 상황은 팀이 확인해야 한다.
