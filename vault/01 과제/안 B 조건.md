# 안 B: 상명대 소프트웨어학과

- 대상: **software.smu.ac.kr**, 우리 학과의 공식 홈페이지 (학과 안내 · 교수 · 연구실 · 교육과정 · 공지)
- 학과 홈페이지가 하는 일
  - **고등학생**에게는 학과를 알린다.
  - **재학생**에게는 필요한 정보를 찾게 한다.
  - 우리가 실제 사용자다. 불편했던 점을 가장 잘 안다.

## 과제에 나온 범위 예시
> 예) 진학할 학과를 알아보는 고등학교 3학년

| | 예 |
|---|---|
| 사용자가 하려는 일 | 무엇을 배우는지 · 졸업 후 어디로 가는지 · 교수와 연구실 보기 |
| 페이지 (4~6쪽) | 메인 · 학과 소개 · 교육과정 · 교수와 연구실 · 졸업 후 진로 |
| 자바스크립트 | 학년별 교육과정 탭 · 교수 카드 강조 · 메뉴 열고 닫기 |
| 범위 밖 | 게시판 글쓰기 · 로그인 · 상명공지 연동 · 졸업작품 영상 |

## 두 안 비교 (안 B 쪽)
| | 안 B: 학과 |
|---|---|
| 사용자 | 고등학생 · 재학생 (우리) |
| 중심 내용 | 교육과정 · 교수 · 진로 |
| 잘 쓰이는 요소 | **표 · 카드 · 탭** |
| 어려운 점 | 정보가 많다. **고르기가 먼저** |

> 어느 쪽이든 점수 기준은 같다. 기준은 기획안의 수용 기준이다.

## ⚠️ 반드시 지킬 규칙

### 안 B 조건
- [ ] **사진 · 로고**: 출처를 밝히고, 쓸 수 없는 것은 직접 만든 그림으로 바꾼다. → [[이미지 출처]]
- [ ] **연락처**: 실제 전화번호 · 이메일은 넣지 않는다. **예시 값**으로 바꾼다.
- 평가: 소프트웨어학과 학생들이 선호도를 평가한다.

### 공통 조건 (공개되는 사이트다)
- [ ] **베끼지 않는다.** 지금 사이트의 화면 · 코드를 복사하지 않는다. 기획부터 다시 한다.
- [ ] **없는 내용을 만들지 않는다.** 지금 사이트에 있는 글 · 사진 · 수치만 쓴다. → [[콘텐츠 재고 총괄]]
- [ ] **개인정보와 전송**: 문의 · 신청 폼은 화면만 만든다. 실제로 보내지 않는다. 폼에 실제 개인정보를 입력하지 않는다.

> [!warning] 콘텐츠를 만들 때 자주 하는 실수
> - 진로 **통계 · 취업률 차트**: 원본에 수치가 없으므로 ❌
> - **CDR 트랙 ↔ 과목 매칭** ("AI 트랙이면 이 과목"): 원본에 없으므로 ❌
> - 2018년 이후 연혁 추가: 원본에 없으므로 ❌ (빈 부분은 "기록 없음"으로 두거나 연혁 범위를 원본대로 표기)
> - 교수 소개 문구 각색: 원본에 있는 세부전공 · 학위 · 경력만 쓴다.
