# 기획안: 상명대 소프트웨어학과 홈페이지 다시 만들기

> 웹프로그래밍 및 AI 에이전트 활용 (2026-2) · 기말 프로젝트 **안 B** · 개인 연습 프로젝트
> 분석 자료: [`/vault`](../../../vault/00%20홈.md) (옵시디언 볼트)
> 진행도: **50%** (목적 · 사용자 · 페이지 구성 · 기능 · 범위 · 수용 기준 초안)

## 1. 목적

**주제: 안 B 상명대 소프트웨어학과 홈페이지(software.smu.ac.kr). 우리가 실제 사용자라서 불편한 점을 가장 잘 알고, 교육과정 · 교수 · 진로처럼 이미 있는 정보를 고르고 연결하는 것만으로도 크게 나아질 수 있어서 골랐다.**

- 지금 사이트는 메뉴 7묶음, 하위 페이지 19개에 정보가 흩어져 있고, 일부는 오래되었거나 비어 있다.
- 우리 사이트는 **"무엇을 배우나 → 누가 가르치나 → 졸업 후 어디로 가나"** 세 질문에 5쪽 안에서 답한다.
- 같은 정보를 **두 단계**로 보여준다. 고3은 요약만 보고, 재학생은 눌러서 상세를 펼쳐본다.

## 2. 사용자

### 주 사용자 (둘 다)
| | ① 진학할 학과를 알아보는 고3 | ② 소프트웨어학과 재학생 |
|---|---|---|
| 상황 | 원서 쓰기 전, 휴대폰으로 둘러본다 | 수강신청 전, 과목과 교수를 확인한다 |
| 하려는 일 | 무엇을 배우는지, 누가 가르치는지, 졸업 후 진로 | 학년 · 학기별 과목과 해설, 교수 연구실, 학사일정 · 공지 바로가기 |
| 필요한 것 | 한 흐름으로 이어지는 소개, 쉬운 말 | 빠른 탭 · 필터, 바로 펼쳐지는 해설 |

### 지금 사이트에서 불편한 점 세 가지
1. **알고 싶은 정보가 여러 메뉴에 흩어져 있다.** 배우는 것 · 교수 · 진로를 보려면 교육과정, 교수소개, 연구실소개, 졸업 후 진로, SM-CDR을 오가야 한다. 교수와 연구실이 다른 메뉴에 있고, 교수 카드의 🏠 아이콘이 연구실 링크라는 설명도 없다.
2. **오래되거나 비어 있고, 깨진 곳이 있다.** 메인 '포토갤러리' 카드는 404 오류가 난다. 졸업작품전 페이지는 캠퍼스 사진 한 장뿐이다. 학과연혁은 2017년에서 멈췄고, 메인 취업정보에는 2018년 글이 떠 있다.
3. **교육과정을 보기 불편하고, 모바일 화면이 깨진다.** 학년 탭을 누를 때마다 페이지 전체가 새로 로딩되고, 과목 설명은 다른 페이지로 이동해야 볼 수 있다. 모바일 메인에서는 게시판 영역이 겹친다.

## 3. 페이지 구성

5쪽으로 시작하고, 시간이 남으면 6쪽을 추가한다.

```
메인
├ 학과 소개      ← 교육목표 + 학과장 인사말 + 연혁 + 학과사무실
├ 교육과정       ← 교육과정 + 교과목 해설
├ 교수 · 연구실  ← 교수 + 명예교수 + 연구실
├ 졸업 후 진로   ← 졸업 후 진로 + SM-CDR
└ (학과 생활)    ← 학사일정 스냅샷 · 공지 바로가기 · 사무실   [시간 남으면]
```

| # | 페이지 | 파일 | 내용 |
|---|---|---|---|
| 1 | 메인 | `index.html` | 학과장 인사말의 핵심 가치 문구, 세 질문 카드, "학과가 궁금해요"와 "재학생 바로가기" 두 갈래 입구 |
| 2 | 학과 소개 | `about.html` | 학과소개, 교육목표 4개, 주 6시간(이론 3 + 실습 3) 심화기초, 학과장 인사말, 연혁(1989~2017), 학과사무실 |
| 3 | 교육과정 | `curriculum.html` | 2026학년도 41과목, 학년 · 학기별, 이수구분 · 학점 · PBL, 과목 해설 |
| 4 | 교수 · 연구실 | `faculty.html` | 교수 7명 + 명예교수 1명 카드, 세부전공 · 연구실 위치, DSPlab · LOG:Lab 소개 |
| 5 | 졸업 후 진로 | `career.html` | 진출 기업, 진로 분야 8개, SM-CDR 진로 트랙 6개 |
| 6 | 학과 생활 *(선택)* | `life.html` | 학사일정 스냅샷(2026-11-26 기준) + 원본 링크, 공지 바로가기, 학과사무실 |

6쪽을 만들기 전까지는 학사일정 · 공지 링크를 메인의 "재학생 바로가기"에 둔다.

## 4. 기능 (자바스크립트)

| 페이지 | 기능 | 설명 |
|---|---|---|
| 공통 | 메뉴 열고 닫기 | 모바일 햄버거 메뉴. 메뉴가 열려 있을 때 Esc나 바깥 영역을 누르면 닫힌다 |
| 학과 소개 | 연혁 접고 펴기 | 시대별(1989~1999 / 2000~2014 / 2015~2017)로 묶어서 접고 편다 |
| 교육과정 | **학년별 탭** | 1~4학년 탭. 페이지를 새로 불러오지 않고 바로 바뀐다 |
| 교육과정 | **필터** | 전공선택 · 전공심화 · PBL 칩으로 과목을 걸러낸다 |
| 교육과정 | **해설 펼치기** | 과목을 누르면 그 자리에서 해설이 펼쳐진다 |
| 교수 · 연구실 | **교수 카드 강조** | 마우스를 올리거나 포커스가 가면 강조된다. 누르면 학위 · 경력 · 연구실 상세가 펼쳐진다 |
| 졸업 후 진로 | 트랙 카드 | 진로 트랙 카드 6개 강조 |

교육과정 데이터는 `data/courses-2026.json`(원본에서 수집)을 JS로 읽어 화면에 그린다.

## 5. 범위 밖

- 게시판 글쓰기, 로그인, 상명공지 실시간 연동, 졸업작품 영상
- 졸업작품전 페이지 (원본에 내용이 없음)
- 포토갤러리 · 학과소식 (원본 자료가 2015~2023년으로 오래됨)
- 영어 페이지, 지도 API, 문의 폼 실제 전송

## 6. 디자인

- **학교 남색을 유지하면서 현대적으로.** 주조색은 남색, 보조색은 연한 파랑이다.
- 원본의 화면과 코드는 복사하지 않는다. 색 계열만 참고하고 레이아웃은 새로 설계한다.
- 이미지 버튼 대신 CSS · SVG로 만들고, 모바일 우선 반응형으로 설계한다. 손가락 확대를 허용한다.
- 화면 구성은 표 · 카드 · 탭 위주로 한다.

## 7. 콘텐츠 규칙

- 지금 사이트에 있는 글 · 사진 · 수치만 쓴다. (진로 통계 ❌, 진로 트랙과 과목을 연결하기 ❌, 2018년 이후 연혁 ❌)
- **교수 사진: 원본 사진에 출처를 표기한다.** 사진이 없는 교수(박한샘)는 직접 만든 그림으로 대체한다.
- 그 밖에 쓸 수 없는 이미지는 직접 만든 그림으로 바꾼다.
- **실제 전화번호 · 이메일은 넣지 않는다.** 예시 값(`041-000-0000`, `example@example.com`)을 쓴다.
- 출처는 푸터와 해당 페이지 하단에 표기한다: "자료 · 이미지 출처: 상명대학교 소프트웨어학과 홈페이지 (software.smu.ac.kr), 2026-11-26 수집"

## 8. 수용 기준 (검수표 초안)

### 공통
- [ ] 5쪽이 모두 열리고, 헤더 메뉴로 서로 이동할 수 있다
- [ ] 폭 360px부터 1440px까지 가로 스크롤 없이 보인다
- [ ] 모바일 메뉴가 열리고 닫힌다 (버튼, Esc)
- [ ] 키보드만으로 모든 링크 · 탭 · 펼치기를 조작할 수 있다
- [ ] 실제 전화번호 · 이메일이 없다
- [ ] 이미지마다 출처가 표기되어 있다
- [ ] 원본 사이트에 없는 수치나 문구가 없다

### 메인
- [ ] 세 질문(배우는 것 · 교수 · 진로)에서 해당 페이지로 한 번에 이동한다
- [ ] "재학생 바로가기"에서 교육과정 · 교수 · 학사일정 · 공지로 이동한다

### 학과 소개
- [ ] 교육목표 4개와 주 6시간 심화기초 과정이 보인다
- [ ] 연혁이 시대별로 접히고 펴지며, 범위(1989~2017)가 표기되어 있다

### 교육과정
- [ ] 학년 탭을 누르면 페이지를 새로 불러오지 않고 해당 학년 과목만 보인다
- [ ] 필터(전공선택 · 전공심화 · PBL)를 적용하면 맞는 과목만 남는다
- [ ] 과목을 누르면 그 자리에서 해설이 펼쳐진다
- [ ] 2026학년도 41과목이 원본과 일치한다

### 교수 · 연구실
- [ ] 교수 8명(명예교수 포함) 카드가 보인다
- [ ] 카드에서 세부전공과 연구실 위치를 바로 볼 수 있다
- [ ] 연구실이 있는 교수(배동성, 이성주)는 카드에서 연구실 소개로 이어진다

### 졸업 후 진로
- [ ] 진출 기업, 진로 분야 8개, 진로 트랙 6개가 원본과 일치한다
